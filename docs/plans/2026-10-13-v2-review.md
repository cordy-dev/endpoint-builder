# Ревью 1.7 и дизайн 2.0.0

**Дата:** 2026-10-13

## 1. Что было сломано в 1.x

Всё ниже воспроизведено на коде 1.7 и проверено тестами в 2.0 (`tests/reliability.test.ts`, `tests/auth.test.ts`, `tests/utils.test.ts`).

### Критичное

| # | Проблема | Где | Последствие |
|---|---|---|---|
| 1 | `timeout` и `signal` не попадают в `fetch`: `_buildConfig` их не копирует | `HttpClient._buildConfig` | Таймауты и отмена не работали вообще, запрос мог висеть бесконечно |
| 2 | Сетевые ошибки глотались (`catch` без rethrow), ретрай проверял только `response && !response.ok` | `HttpClient._execute` | `retryOnNetworkError` не работал, вместо ошибки получался `Error("HTTP fetch")` |
| 3 | Классы `HttpError` / `NetworkError` никогда не выбрасывались: бросался `Error`, приведённый к интерфейсу `HttpError` из `types.ts` с тем же именем | `_execute`, `types.ts` | `instanceof HttpError` и `error.type === "http"` всегда ложны. Тип `ApiError` не соответствовал рантайму |
| 4 | `refreshAuth` и `handleRequestError` делали `continue` без счётчика | `_execute` | Бесконечный цикл, если сервер продолжает отвечать 401 |
| 5 | Dedupe включён по умолчанию для **всех** методов, ключ без заголовков, `JSON.stringify(FormData) === "{}"` | `_dedupeKey` | Два разных POST или upload склеивались в один запрос. Ответы с разной авторизацией смешивались |
| 6 | Subpath-экспорты `./auth`, `./retry`, `./storage` указывали на файлы, которых нет в `dist` (tsdown собирал только `index`) | `package.json`, `tsdown.config.ts` | `import "@cordy/endpoint-builder/auth"` падал у пользователей |
| 7 | POST/PATCH ретраились на 5xx | `ExponentialRetryStrategy` | Повторные платежи и дубли записей |

### Серьёзное

- `ApiKeyStrategy` с `asQueryParam` менял `url` у временного `Request`, который сразу выбрасывался, поэтому ключ не добавлялся.
- `buildPath`: `replace(":id")` срабатывал на `:idx`, значения не кодировались (`/` и `?` в параметре ломали URL).
- Тип `ExtractParamNames<"/files/:name.json">` давал `"name.json"`, порты (`localhost:3000`) тоже считались параметрами.
- `form(data)` ставил `x-www-form-urlencoded`, но отправлял `FormData`. `form(data, false)` ставил `multipart/form-data` вручную, без boundary, и сервер не мог разобрать тело.
- `.data()` эвристически парсил любую строку, похожую на JSON.
- Тело ошибочного ответа не читалось: `error.response.data` всегда `undefined`.
- Тела отброшенных ответов (ретраи, 401) не освобождались. В undici это держит сокет keep-alive.
- `basicAuth` через `btoa` падал на не-ASCII.
- Тип `StandardSchemaIssue.path` был уже спецификации, из-за чего реальные схемы zod/valibot могли не подходить по типам.
- Ожидание перед ретраем (`setTimeout`) нельзя было прервать.

### Архитектура и DX

- Три фасада (`TypedClient`, `UniversalClient`/`SimpleClient`, `HttpClient`) и ~800 строк копипасты `get/post/put/...`.
- Мутабельный `RequestBuilder`: переиспользование частично настроенного билдера давало протекающее состояние.
- `RequestBuilder` не был thenable, а `SchemaRequestBuilder` был. В одной цепочке `await` вёл себя по-разному.
- Ответ всегда `unknown` или `any`. Не было типизированных ошибок по статусам, не было валидации body и query.
- `storage` по умолчанию создавался (`localStorage`), но ядром не использовался.

## 2. Принципы 2.0

1. **Сквозная типизация, как в Elysia.** Типы выводятся из строки пути и схем. `.errors({ 404: S })` накапливает типы ошибок на уровне клиента и запроса, `isHttpError(e, 404)` сужает `body`.
2. **Билдеры, как в .NET** (`IHttpClientBuilder`, `HttpRequestMessage`, `DelegatingHandler`). `ClientBuilder` и `RequestBuilder` иммутабельны и ленивы. Middleware-пайплайн собирается один раз на клиента.
3. **Любые валидаторы.** Поддерживаются Standard Schema v1 (zod, valibot, arktype, effect, yup), `parse()`-объекты и функции. Синхронные валидаторы выполняются синхронно.
4. **Надёжность по умолчанию.** Таймаут на попытку покрывает и чтение тела. Ретраятся только идемпотентные методы. Refresh single-flight и без циклов. Отмена в dedupe у каждого вызывающего своя. Тела отброшенных ответов освобождаются.
5. **Честные ошибки.** Шесть классов с дискриминатором `type`. `.safe()` ловит только ошибки библиотеки, баги в пользовательском коде пробрасываются.

## 3. Архитектура

```
Client (immutable config + composed pipeline)
 ├─ get/post/... ─▶ RequestBuilder<TData, TErrors>  (immutable, thenable)
 │                     prepare: params → query → body (validate + encode)
 │                     pipeline: hooks → dedupe → user middleware → retry → auth → transport(fetch + timeout)
 │                     handle: status → decode → unwrap → validate → map
 └─ api(contract) ─▶ { users: { get(input) → RequestBuilder } }
```

| Модуль | Ответственность |
|---|---|
| `core/client.ts` | `ClientBuilder`, `Client`, `createClient`, сборка пайплайна |
| `core/request.ts` | `RequestBuilder`: состояние, подготовка, обработка ответа |
| `core/transport.ts` | `fetch` + таймаут + маппинг ошибок транспорта |
| `contract/` | `endpoint.*`, `defineContract`, привязка к клиенту |
| `retry/` | Политика и middleware |
| `auth/` | `bearer`, `apiKey`, `basic`, `refreshable` + middleware |
| `middleware/` | Тип `Middleware`, `compose`, dedupe |
| `schema/` | Standard Schema, `validate`, `InferInput`/`InferOutput` |
| `errors/`, `result.ts` | Иерархия ошибок, `Result` |
| `utils/` | path, query, body, decode, headers, url, signal |

## 4. Производительность

- Пайплайн компонуется один раз на клиента. Middleware без работы (нет auth, нет dedupe, нет политики) проходят синхронно, без лишнего промиса.
- Нет `new URL` / `new Request` на запрос, только строковая склейка.
- Синхронный путь валидации.
- Микробенчмарк с фейковым `fetch` показывает накладные расходы на уровне 1.7, хотя 2.0 делает больше: реальные таймауты, ретраи, валидацию. Основное время уходит в `Response` и стримы undici.
- Реальный выигрыш даёт корректность: нет лишних дубликатов POST, сокеты освобождаются, нет retry-штормов на неидемпотентных методах.

## 5. Что можно добавить дальше

- Прогресс загрузки и скачивания (`onDownloadProgress` через стрим).
- Кэш-middleware (ETag / `If-None-Match`) и rate-limit/circuit-breaker middleware в стиле Polly.
- Генерация контракта из OpenAPI и экспорт контракта в OpenAPI.
- Интеграция с TanStack Query (`queryOptions` из endpoint).
- SSE и стриминговый JSON (NDJSON) для ответов.
